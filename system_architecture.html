🇧🇩 NATIONX

Full System Architecture

Node.js + Express + MySQL · 3-Tier Architecture · 117 Tables · 20 Modules · REST API
1. Architecture Overview
NATIONX is a full-stack web application implementing a 3-Tier Client-Server Architecture for Bangladesh's central government digital services. The system follows a monolithic MVC pattern with a RESTful API backend, static HTML/CSS/JS frontend, and a MySQL relational database with 117 normalized (3NF) tables, stored procedures, triggers, and views.

8. Security Architecture

🔐 Authentication

JWT tokens with expiration. Bcrypt password hashing. Separate admin auth system with approval workflow.

🛡️ HTTP Security

Helmet middleware: Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, XSS-Filter.

⏱️ Rate Limiting

100 requests per 15 minutes per IP on all /api/* endpoints. Prevents brute-force and DDoS.

✅ Input Validation

express-validator on all form inputs. Parameterized SQL queries (prepared statements) prevent SQL injection.

📁 File Upload Security

Multer with 5MB limit. File type restrictions. Separate upload directories per module (nid/, passport/, etc.)

📝 Audit Trail

audit_log table tracks all CRUD operations. admin_actions_log tracks admin changes. login_logs for access monitoring.

9. Database Architecture
Design Pattern: Star schema centered on reg_info (user hub). All modules FK-reference reg_info.id. Geography normalized into divisions → districts → upazilas lookup chain. Payment and status lookups are shared across modules for consistency.

Normalization: All 117 tables are in 3rd Normal Form (3NF). No transitive dependencies. Junction tables for M:N relationships. Proper FK constraints with cascading rules.

Advanced Features: Stored procedures for complex operations. Triggers for automatic audit logging. Views for reporting aggregation. Indexes on all PK, UK, and FK columns for query performance.
